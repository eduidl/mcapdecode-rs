# Migrating from v0.10 to v0.11

v0.11.0 reworks the `mcapdecode` reader API. A `McapReader` is now an opened
file, and every read goes through one builder, `McapReader::read()`, which
selects topics or channels, a time range, and an output (`raw()`, `decoded()`,
or `arrow()`). The path-based methods of v0.10 are removed.

This guide maps the v0.10 API to v0.11. For the full API, see the
[README](https://github.com/eduidl/mcapdecode-rs/blob/main/README.md) and the
crate documentation.

## Opening files and configuring decoders

v0.10:

```rust
let reader = McapReader::builder()
    .with_default_decoders()
    .with_parallel(false)
    .build();
reader.list_topics(Path::new("sample.mcap"))?;
```

v0.11:

```rust
let reader = McapReader::builder()
    .with_parallel(false)
    .open("sample.mcap")?;
reader.topics();

// Or, with the built-in decoders and default settings:
let reader = McapReader::open("sample.mcap")?;
```

- `McapReader::open(path)` opens a file with every built-in decoder enabled by
  cargo features. Opening reads the memory map and summary once; all later
  queries and reads reuse them. An MCAP summary is required, as before.
- `McapReader::builder()` now starts with the built-in decoders.
  `with_default_decoders()` is removed; call `clear_decoders()` to start empty.
- `McapReaderBuilder::open(&self, path)` replaces `build()`. It takes `&self`,
  so one builder opens any number of files with the same configuration.
- `with_decoder` takes the decoder by value instead of a `Box`.
  `with_shared_decoder` takes an `Arc<dyn MessageDecoder>`.
- `McapReader::new`, `Default for McapReader`, `register_decoder`, and
  `register_shared_decoder` are removed. Use the builder.
- The built-in decoders are re-exported from `mcapdecode::decoder`
  (`ProtobufDecoder`, `PresencePolicy`, `Ros2IdlDecoder`, `Ros2MsgDecoder`,
  `RawJsonDecoder`, behind their features), so changing a decoder's settings
  needs no direct dependency on a decoder crate:

  ```rust
  use mcapdecode::decoder::{PresencePolicy, ProtobufDecoder};

  let reader = McapReader::builder()
      .with_decoder(ProtobufDecoder::new_with_presence_policy(PresencePolicy::AlwaysDefault))
      .open("sample.mcap")?;
  ```

## Reading messages

v0.10:

```rust
let options = ReadOptions {
    time_range: Some(TimeRange { start: Some(start), end: Some(end) }),
    ..Default::default()
};
reader.for_each_decoded_message_with_options(path, "/pose", &options, |message| {
    println!("{}", message.log_time);
    Ok(())
})?;
```

v0.11:

```rust
reader
    .read()
    .topic("/pose")
    .time_range(start..end)
    .decoded()
    .for_each(|channel, message| {
        println!("{}: {}", channel.topic, message.log_time);
    })?;
```

| v0.10 | v0.11 |
| --- | --- |
| `for_each_decoded_message(path, topic, f)` | `read().topic(topic).decoded().for_each(f)` |
| `for_each_decoded_message_by_channel_id(path, id, f)` | `read().channel(id).decoded().for_each(f)` |
| `for_each_topic_decoded_message(path, topics, f)` | `read().topics(topics).decoded().for_each(f)` |
| `for_each_raw_message(path, topic, f)` | `read().topic(topic).raw().for_each(f)` |
| `for_each_raw_message_by_channel_id(path, id, f)` | `read().channel(id).raw().for_each(f)` |
| `for_each_record_batch(path, topic, f)` | `read().topic(topic).arrow().for_each(f)` |
| `for_each_topic_record_batch_with_options(path, topics, options, f)` | `read().topics(topics).arrow().for_each(f)` |
| `with_prepared_topic(path, topic, f)` / `PreparedTopic` | Reuse the opened `McapReader` |
| `*_with_options` variants | Set the options on `Read` (below) |

- Without `topic`/`topics`/`channel`/`channels`, a read selects every channel
  in the file. Decoded and Arrow reads fail if a selected channel cannot be
  decoded.
- Every callback receives the originating `&ChannelInfo` as its first argument.
- Raw reads now accept several topics or channels and a time range, and honor
  the parallel setting like decoded and Arrow reads.

### Read options

`ReadOptions`, `TimeRange`, and `RecordBatchOptions` are no longer public.
Set the same options on the builder:

| v0.10 | v0.11 |
| --- | --- |
| `ReadOptions::time_range: Some(TimeRange { start, end })` | `Read::time_range(range)` |
| `ReadOptions::parallel: Some(b)` | `Read::parallel(b)` |
| `ReadOptions::offset`, `ReadOptions::limit` | Removed (see below) |
| `RecordBatchOptions::batch_size` | `ArrowRead::batch_size(n)` |
| `RecordBatchOptions::metadata` | `ArrowRead::metadata(columns)` |

`time_range` accepts any `RangeBounds<u64>` over `log_time` in nanoseconds,
such as `start..end`, `start..`, `..=end`, or the inclusive range returned by
`McapReader::message_time_range()`. The v0.10 `TimeRange { start, end }` was
inclusive at the start and exclusive at the end, which is `start..end`.

`offset` and `limit` are removed because their per-topic meaning did not fit
multi-topic reads. To stop after a number of messages, break from
`try_for_each`; to resume a scan, start the next read's time range after the
last `log_time` seen.

### Callbacks and stopping early

As with `Iterator`, `for_each` callbacks return `()`. Callbacks that can fail
or stop move to `try_for_each`, which accepts `Result<(), E>`,
`ControlFlow<()>`, or `Result<ControlFlow<()>, E>`, where `E` is
`Box<dyn Error + Send + Sync>`:

```rust
use std::ops::ControlFlow;

let mut messages = Vec::new();
reader.read().topic("/pose").decoded().try_for_each(|_, message| {
    messages.push(message);
    if messages.len() >= 100 { ControlFlow::Break(()) } else { ControlFlow::Continue(()) }
})?;
```

`Err` fails the read with `McapReaderError::Callback`, as in v0.10. `Break`
ends the read with `Ok(())`; in parallel reads it also cancels the workers.
A closure whose only return is `Err(...)` needs a type annotation such as
`Err::<(), _>(...)`.

## Metadata and schemas

`McapReader` keeps only `topics()`, `channels()`, `summary()`, and
`message_time_range()` for file metadata. Schemas are derived from the same
selection as a read:

| v0.10 | v0.11 |
| --- | --- |
| `list_topics(path)` | `topics()` |
| `list_channels(path)` | `channels()` |
| `message_count(path, topic)` | Sum `message_count` over `read().topic(topic).selected_channels()?`, or use `TopicInfo::message_count` |
| `topic_field_defs(path, topic)` | `read().topic(topic).field_defs()?` |
| `field_defs_by_channel_id(path, id)` | `read().channel(id).field_defs()?` |
| `topic_schema(path, topic)` / `TopicSchema` | `read().topic(topic).field_defs()?` with `ChannelInfo::schema` |
| `topic_batch_schema(path, topic, options)` | `read().topic(topic).arrow().metadata(columns).schemas()?` |
| `list_topics_with_decode_status(path)` / `TopicDecodeStatus` | `read().channel(id).field_defs()` per channel, with `McapReaderError::is_unsupported_channel()` |

- `field_defs()` and `schemas()` return one entry per selected channel, as
  `Vec<(ChannelInfo, _)>`, since the channels of one topic may have different
  schemas. `ArrowRead::schemas()` uses the read's metadata columns, so the
  declared schema matches the emitted batches.
- `McapReaderError::is_unsupported_channel()` is true when a channel cannot be
  decoded with the registered decoders (no schema, no decoder for its
  encodings, or a schema that cannot be parsed or derived). Such channels can
  still be read with `raw()`.
- `McapReader::summary()` returns the `mcap::read::Summary` read at open time,
  and `message_time_range()` returns the inclusive `log_time` range from the
  summary statistics or chunk indexes. `mcapdecode::mcap` re-exports the `mcap`
  crate, which is now part of the public API.

### Topics with multiple channels

Selecting a topic now reads all of its channels instead of failing with
`McapReaderError::MultipleChannels`, which is removed. Use `ChannelInfo::id` in
callbacks to tell the channels apart, or select one with `channel(id)`.

### `ChannelInfo` and `TopicInfo`

- `ChannelInfo::schema_name` and `schema_encoding` are replaced by
  `schema: Option<ChannelSchema>`, with `name` and `encoding`. It is `None` for
  a channel with schema id 0. A schema with an empty encoding is kept as
  `SchemaEncoding::None`.
- `ChannelInfo::message_encoding` is a `MessageEncoding` instead of a `String`,
  and `ChannelSchema::encoding` is a `SchemaEncoding`. Both enums are
  re-exported at the crate root. `McapReaderError::NoDecoder` uses them too.
- `TopicInfo` drops `schema_name`, `schema_encoding`, and `message_encoding`,
  which described only its first channel. Read them from `channels()`.

### Errors

- Removed: `McapReaderError::MultipleChannels` and `StatsNotAvailable`.
- Added: `McapReaderError::MessageIndexNotAvailable`, returned by `latest()`.

## Crate re-exports

`mcapdecode::core` is removed; its name shadowed the built-in `core` crate.

| v0.10 | v0.11 |
| --- | --- |
| `mcapdecode::core::{Value, FieldDefs, DataTypeDef, ...}` | `mcapdecode::{Value, FieldDefs, DataTypeDef, ...}` |
| `mcapdecode::core::{MessageDecoder, TopicDecoder, DecoderError, EncodingKey}` | `mcapdecode::decoder::{...}` |
| `mcapdecode::core::format_field_defs(&fields)` | `fields.to_string()` (`FieldDefs` implements `Display`) |
| `mcapdecode::arrow` (the `mcapdecode-arrow` crate) | `mcapdecode::arrow` is now the `arrow` crate itself |
| `mcapdecode::{JsonlWriter, JsonlWriterBuilder, Integer64Encoding, NonFiniteFloats}` | `mcapdecode::batch::{...}` |
| `mcapdecode::arrow::{flatten_record_batch, project_record_batch, FlattenPolicy, ...}` | `mcapdecode::batch::{...}` |

`MessageBatchSchema`, `MetadataColumns`, `MetadataTimestampFormat`, and
`ArrowConvertError` stay at the crate root. With `mcapdecode::arrow` naming the
`arrow` crate, callers can use `RecordBatch` without depending on a matching
`arrow` version.

## Decoded values

### Accessors report null as an error

The exact-type accessors (`try_i8` … `try_u64`, `try_bool`, `try_f32`,
`try_f64`, `try_str`, `try_bytes`) now return `Result<T, ValueAccessError>`
instead of `Result<Option<T>, ValueTypeError>`, and report null as
`ValueAccessError::NullValue`. They chain with `get()` and each other under one
error type. Where null is expected, such as an unset protobuf `optional` field,
convert it with `non_null()`:

```rust
// v0.10
let count: Option<i32> = value.try_i32()?;

// v0.11
let count: Option<i32> = value.non_null().map(Value::try_i32).transpose()?;
```

`ValueAccessError` converts from `ValueTypeError`, so a function returning
`ValueAccessError` can still use `?` on code that produces `ValueTypeError`.

### Structs carry their schema

- `Value::Struct` holds a `StructValue` instead of `Vec<Value>`. `StructValue`
  derefs to the values, `into_values()` returns them, `schema()` returns the
  shared `Arc<StructDef>`, and `fields()` iterates `(name, value)` pairs.
  Build one with `Value::structure(schema, values)`. `Vec<Value>::into()`
  builds a struct with an empty schema, on which name lookup fails with
  `ValueAccessError::SchemaMismatch`.
- `DataTypeDef::Struct` holds an `Arc<StructDef>`. Build it with
  `DataTypeDef::structure(def)` or wrap the definition in an `Arc`. Matching
  `DataTypeDef::Struct(def)` and reading `def.fields` works as before.
- Custom decoders build mismatch errors with `Value::type_mismatch(ValueType)`
  instead of a type name string. Free-text descriptions still use
  `ValueTypeError::new`.
- `decode_cdr_to_value` and `decode_protobuf_to_value(_with_policy)` now derive
  the schema on every call. Use the topic decoders to decode many messages.

### New accessors

These are additions and need no migration:

- `get("name")` for struct fields and string map keys, `get(index)` for list and
  array elements, `get_key(key)`, `as_sequence()`, and `as_map()`.
- `get_path("poses.0.position.x")` for dotted paths, and `FieldPath` to resolve a
  path once against a schema and reuse it for every message.
- `try_widen_i64()`, `try_widen_u64()`, and `try_widen_f64()` for lossless
  widening, and `try_lossy_f64()` for any number as `f64`.
- `try_shared_bytes()` for the `Arc<[u8]>` of `Bytes` and `Uint8List` values.
- `is_null()`, `non_null()`, and `DataTypeDef::is_numeric()`.

## Behavior changes

- When chunk indexes exist, raw reads visit only indexed chunks, so messages
  outside chunks are no longer returned, matching decoded and Arrow reads.
- `transmcap` writes all channels of a topic to one output when their schemas
  match, and fails when they differ.
